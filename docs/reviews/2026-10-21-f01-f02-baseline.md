## F01 dispatch fence

The primary static/native renderer checked currentness before an awaited marker registration,
then sent the command without checking again. Recheck semantic projection, current owner,
loaded presentation and guard after metadata awaits; recheck availability immediately before
send. Selective Hue actions retain their per-member currentness/availability checks. Do not
retry, broaden a scene scope or alter ownership classification.

Regression coverage injects Manual appearance and Manual-OFF at owner-read, Hue-read,
guard and marker boundaries across all four surfaces and Daily/Holiday. Additional cases
change availability, presentation, guard, generation and owner during registration, and
exercise selective scenes. Front Eve has one managed leaf, so a mixed selective scene is
not manufactured for it.

## Scope and deployment impact

F01 changes the legacy renderer only. F02 changes HLM deferred correlation only.
The review branch also adds focused tests and this baseline/validation documentation.
No helper, service schema, projection schema, persistence version, manifest, YAML or automation
change is required. Neither repair converts Spa/49ers families or changes receipt attribution.

A future full repair requires BOTH changed Python components; an HLM-only HACS update would
install F02 but leave F01 unfixed. Use the reviewed HLM + legacy combination; preserve the
currently loaded package/automations. HLM remains without a lighting-dispatch path.
F03–F12 and runtime-only functional command paths remain separate review work.
